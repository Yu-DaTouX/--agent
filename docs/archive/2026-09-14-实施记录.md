## 2. 逐项说明（按方案编号）

### 阶段 1

| 编号 | 做法 |
| --- | --- |
| N17 / 7.4 缓存 | 两位小数**截断**（99.999% 不四舍五入成 100%），只有原始比例 = 100% 才显示 `100%`；0 分母显示 `—`；流式期间未结算显示「待结算」，不拿上一轮比例冒充 |
| N07 / 4.2 历史详情 | `canExpand` 恒真：**查看权限**与**自动展开偏好**分开。`toolDetail` 语义改为「运行中是否自动展开」，带 `toolDetailV2` 迁移标记（老配置的 `false` 是默认值、不代表偏好，一次性升级为 true） |
| N02 / 3.2 欢迎页 | 主标题「从一个编码任务开始。」+ 当前项目路径（次级）+ 三个编码入口；标签与草稿分离；无项目时引导选项目；删掉未经验证的记忆承诺 |
| N18 / 第 15 节 删除 | 确认 → 进行 → 成功（关模态 + 左栏可撤销通知）→ 失败（框内原因）；标题改「将会话移入回收站？」；不再借用 `.send`（按钮 30px、文字不换行）；补恢复失败与列表刷新失败的反馈 |
| N12 / 5.1 拖放 | 新增 `main/file-refs.ts`：路径经 `webUtils` → 主进程 **realpath 校验 + 进程内授权登记**；文本只把路径交给模型按需读取；上限 20 个 / 图片合计 20MB；纯文本拖入保留浏览器默认行为 |
| N13 / 5.2 链接 | 新增 `shared/links.ts`（`classifyLink` 纯函数）；http(s) → 内部浏览器，文件路径 / `path:42` → 只读预览，`javascript:`/`data:` 等明确拒绝；相对路径按会话 cwd 解析且必须落在 cwd 内 |
| 5.2 文件预览 | 右侧 `FilePreviewPane`：只读、文本 2MB 截断带行号、二进制只给元信息、复制路径 / 定位 / 用默认程序打开；打开时 `browser.setVisible(false)` 隐藏原生视图，关闭恢复 |

### 阶段 2

| 编号 | 做法 |
| --- | --- |
| 4.1 工具分型 | `detailKind()` 分三类：命令 → 紧凑终端；edit/write → 文件改动卡片；其余（搜索/读取/浏览器）→ 直接给结果，不再套终端外壳。运行行加低对比度扫光（**非唯一状态信息**），取消状态独立显示（`cancelled` 走 `--warn`，不染红） |
| 4.3 紧凑命令 | 默认高度 240 → **84px**（1 行命令 + 2 行输出）；去掉三色装饰灯、重复命令、重复状态胶囊；上限 72vh → 60vh；双击复位回紧凑默认值 |
| 4.2 并行展开 | 多个调用并行时只有**最新开始**的那条自动展开（`autoOpen`）；展开/收起用 `lib/scrollAnchor.ts` 做滚动锚点 —— 正在读历史时视口不被顶走，贴底时保持贴底 |
| 4.4 推理窗口 | 字素级推进（中文标点/emoji 不劈开）；尾部 140ms 淡入；积压超限或从后台切回直接追齐；无待显示文本时停掉 rAF；固定约 3 行 + 可拖尺寸（localStorage 全局记忆，双击复位）；展开/收起保留挂载 + 180ms 高度过渡；上滚暂停跟随并给「回到最新」；遵从 `prefers-reduced-motion` |
| 第 6 节 提问面板 | 新增 `QuestionPanel`（输入区上方、**非模态**、不抢焦点）；收起 ≠ 取消（队列与草稿保留）；IME 组合期间不提交；提交防重；`sensitive` 分类由请求方声明，只对敏感确认保留模态 |
| 7.1 任务高亮 | 行布局固定为 16px 状态槽 / minmax(0,1fr) / 状态说明，间距 ≥ 8px；受阻有独立样式与「受阻」文案（只在数据真的标 blocked 时出现）；运行高亮用内侧 2px 标记 |

### 阶段 3

| 编号 | 做法 |
| --- | --- |
| 7.2 额度 | 主值改为**本月已用**（不再取最紧窗口）；每个窗口一组数字 + 进度条 + 重置说明；月度上限是反推的 → 打「推算」徽标；查询失败保留旧快照并注明更新时间；切 provider 防竞态；超 100% 文字如实、进度条夹取；刷新移到标题区 |
| 7.3 上下文 | 主行「上下文 49% …… 128k / 262k」+ 细进度条；阈值/预留/保留/累计花费收进「详情」折叠；`tokens=null` 的「更新中」处理保留 |
| 3.1 回复详细程度 | `AppSettings.responseDetail`（默认 standard）；内置扩展 `resources/pi-extensions/response-detail.js` 在 `before_agent_start` 注入；**standard 档不注入任何东西**（不改缓存前缀）；模型菜单里三档分段控件 |

### 阶段 4

| 编号 | 做法 |
| --- | --- |
| 5.3 可靠差异 | 新增 `main/snapshots.ts`：写入类工具（edit/write/…）在 `tool_execution_start/end` 各读一次文件（同步、限 2MB），算出行级 patch + 增删行数 + 状态；内容全文**不传给渲染端**；无前置快照 / 大文件如实退化 |
| 第 9 节 浏览器 | 远程网页权限**默认拒绝**并记录请求（界面可查看）；本地预览边界：远程页面发起的回环/私有地址请求被取消；下载显示来源且不自动打开 |
| 第 9 节 沙盒 | 主窗口 `sandbox: true`；为它把 preload 构建改成 **CJS**（sandboxed preload 不支持 ESM，实测过一次空白界面）；IPC 增加来源校验（只接受主窗口 webContents） |

### 阶段 5（自有适配，见 4.1）

- `main/subagents.ts`：每个子任务 = 一个独立 `pi --mode rpc` 子进程；事件流复用 `PiRpc` + `normalizeMessage`；并发上限 2、不嵌套、10 分钟超时、转录有界 200 条。
- 前端：主对话区紧凑运行列表 + 右侧详情（复用消息渲染件）+ 停止；入口是 `/subagent <任务>`（本地命令，不进模型）。
- 退出 / 重启 pi / 换 cwd 时会一并收掉子代理。

### 阶段 6

- **密度**：`AppSettings.density` + `html[data-density]` 覆盖 `--d-row-gap` / `--d-section-gap` / `--d-message-gap`；三档**只改间距不改字号**（standard 档 = 改动前的值）。
- **图标**：在 `DESIGN.md` 补了语义映射表（一个图标只承担一层含义）；像素图标先不替换（未做样张对比）。
- **深浅色**：`light` 场景通过（终端深色底是刻意的）。
- **键盘**：`dialog` 场景补「设置里的控件都能 Tab 聚焦且都是原生控件」。
- **sound**：把「应当响」的断言从固定 80ms 等待改成**轮询**（方案 B4 的 flaky）。
- **设计规范**：`DESIGN.md` 修订「无渐变」为「静态界面不用装饰渐变，只有运行状态允许低对比度扫光」。

## 4. 没做 / 无法验证的（逐条如实列出）

1. **上游子代理扩展未验证**：`nicobailon/pi-subagents` 与 `mjakl/pi-subagent`
   在本机没有安装，也没有可复现的 Windows RPC 事件协议证据。所以阶段 5 走的是
   方案 8.2 明写的兜底——「Yan 自有进程管理适配」。**换上游实现时，前端模型不用改**，
   只要替换 `main/subagents.ts` 的 spawn 部分。
2. **模型自动委派未接通**：子代理入口是 `/subagent <任务>` 与程序化 API，
   模型还不能自己决定派子任务（需要一个「扩展 → 宿主」的上行通道，方案 8.1 的候选
   扩展才有）。
3. **子代理写入隔离未做**：子代理与主会话共享同一个 cwd。只读检查安全；
   写入任务会与主工作区竞争（方案 8.4 建议的独立 Git worktree 没实现）。
4. **回复详细程度的「每轮记录档位」未做**：只有全局设置 + 每轮读一次文件。
5. **浏览器权限只有「默认拒绝 + 可查看」**，没有「显式授权某个站点」的能力。
   DNS 重绑定等更底层的边界也没处理（在代码注释里写明了局限）。
6. **内容层 diff 的归属**：只覆盖受支持的写入工具；shell / 第三方工具产生的改动
   仍然拿不到「这是哪次调用改的」的证据（方案第 14 节第 5 条说的就是这个）。
7. **打包未验证**：preload 改成了 `.cjs`（`electron.vite.config.ts` + 主进程加载路径），
   `electron-builder.yml` 的 `files: out/**` 会带上它，但**没有实际跑过 `dist`**。
   发布前必须跑一次 `npm run dist:dir && npm run test:packaged`。
8. **图标样张未做**：像素图标（Pixelarticons）的 16/24px 与 DPR 对比样张没有生成，
   所以没有替换现有线性图标（这条是方案第 10 节自己要求的顺序）。
9. **Command Code 的月度上限仍是推算值**（weekly.cap × 2），界面上打了「推算」徽标；
   真实账户字段没有凭证去核对。
10. **密度只调了间距，没有调行高倍率**：中文在 12.5px 上是像素对齐的，
    缩放行高会牵动很多量测断言；方案说「只调整间距和行高」，这里保守地只做了间距。
