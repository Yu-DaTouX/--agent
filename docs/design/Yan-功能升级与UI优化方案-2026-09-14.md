## 1. 产品方向与推荐决策

Yan 应围绕编码任务组织体验：看懂需求、查看代码、执行命令、审阅改动、运行验证，以及持续观察子代理。沿用现有 Maple Mono CN 等宽字体、小圆角、细边框和语义色体系，让主对话保持可读，过程默认紧凑、详情随时可查。

本次推荐直接采用以下设计默认值，后续实现不必再逐项重复讨论：

| 项目 | 推荐方案 |
| --- | --- |
| 回复详细程度 | 简洁 / 标准 / 详细，默认标准；独立于现有推理强度 |
| 推理窗口 | 默认显示约 3 行，可调大小并记住全局偏好；手动翻阅时暂停追尾 |
| 命令窗口 | 默认 1 行命令 + 2 行输出，保留拖拽和扩大查看 |
| 历史详情 | 成功、失败、取消均能点击；设置只决定是否自动展开 |
| 普通工具 | 类型图标 + 一行活动摘要；不用终端外壳包裹所有工具 |
| 模型提问 | 放在输入框上方的非模态面板，可同时翻阅消息 |
| 链接 | 网页默认在内部浏览器打开，文件进入只读文件预览 |
| 子代理 | 先验证 `nicobailon/pi-subagents` 的结构化事件适配，Yan 自己绘制预览界面 |
| 密度 | 紧凑 / 标准 / 舒适；默认标准，作为独立批次实施 |
| 额度 | Command Code 按用户指定的已用口径展示，缺失或推算数据单独说明 |
| 图标 | 优先统一现有图标语义；像素图标先做样张，品牌图标采用“砚台 + 光标”方向 |

现有《DESIGN.md》要求“无渐变”，新需求要求运行中的流动光效。建议把规范修订为：静态界面继续不使用装饰渐变，只有运行状态允许低对比度扫光。它是状态反馈，不扩展成全界面的发光边框。实施时先更新设计规范，再调整令牌。

## 3. 回复详细程度与欢迎页

### 3.1 详细程度的含义

在输入区模型设置附近增加小型菜单“回复：标准”，不再添加一整行大型控件。

| 档位 | 输出行为 |
| --- | --- |
| 简洁 | 先给结果、改动摘要和必要验证；减少过程解释 |
| 标准 | 结果、关键原因、改动和验证边界，保持目前默认方向 |
| 详细 | 补充实现取舍、关键步骤、例子与适用边界 |

三个档位均不得省略必要错误提示或改变任务完成范围，也不直接调低推理强度或强制截断输出。

新增 `responseDetail` 设置，默认 `standard`，旧配置缺失时回落到标准；当前选择在下一条发送时生效，运行中的请求不改写。首期全局记忆，发送时记录该轮采用的档位，避免重开历史时误读。

接入建议：沿用 `resources/pi-extensions/question.js` 已采用的 `before_agent_start` 提示注入模式，增加独立回复偏好扩展。请求开始时读取一次有效设置，不逐 token 修改提示。标准档尽量保持原提示不变；切换档位可能改变提示前缀和缓存表现，应测试切换、重启及排队消息的生效时机。只有确认当前 provider/运行时支持原生参数后才添加原生适配，不能把一个通用 UI 值直接发给所有 provider。

涉及：`shared/ipc.ts`、`main/settings.ts`、`main/agent.ts`、`state/store.ts`、`Pickers.tsx`、设置页和新增内置扩展。界面必须分别写明“回复详细程度”和“推理强度”。

### 3.2 欢迎页文案与行为

建议主标题：**从一个编码任务开始。**

辅助文案：**描述你想实现的功能，或拖入文件，一起查看代码、定位问题与验证改动。**

当前项目路径显示为次级信息。下方只保留三个轻量入口：“了解这个项目”“定位一个问题”“审阅最近改动”。点击后填入可编辑草稿，由用户发送，不自动运行命令。没有选定项目时，“了解这个项目”引导选择项目。

移除未经功能保证的记忆承诺，更新中英文文案；欢迎页不出现密集功能介绍。

## 4. 统一过程展示：推理、命令、普通工具

### 4.1 视觉结构

```text
[搜索图标] 正在搜索 Composer 的附件处理                 扫光
[终端图标] 正在运行 npm run typecheck                   扫光
  > npm run typecheck
  最近一行输出
  最新一行输出
[修改图标] 已修改 Composer.tsx                           查看改动
```

运行行始终保留工具类型图标，扫光或小型状态指示承担“运行中”提示。成功后停止动画，失败显示明确状态与详情入口，取消单独显示。不要用动画作为唯一状态信息。

将详情分为 `CommandDetail`、`FileChangeDetail`、`ToolResultDetail`，可先由现有 `TerminalWindow`/`ToolDetail` 拆分实现。搜索、读取、浏览器操作不再套终端标题栏。摘要仍由现有工具识别逻辑提供，未知工具显示通用图标和真实名称。

### 4.2 自动展开与用户操作

- 所有已记录调用都可查看详情；没有保留内容时，点击后说明缺失原因。
- `toolDetail` 改为“运行时自动展开详情”的偏好，不再控制历史查看权限。
- 当前运行的命令自动展示紧凑输出；普通工具默认一行。
- 用户手动展开后不被后续事件强制收起；自动展开的命令在完成后回到一行，错误保留醒目入口。
- 多个调用并行时，默认只有当前选中命令展开，其余保持活动行，避免填满主对话。
- 展开、收起前后以当前工具行为滚动锚点；用户正在阅读历史时，不被整页拉回底部。

### 4.3 紧凑命令窗口

默认内容区为 1 行命令和 2 行尾部输出，总高度预计约 80–110px，随字体和密度实测调整。去掉三色装饰灯、重复目标和重复状态；完整命令在历史详情中换行显示并可复制。

保留下方、右侧和右下角调节；宽度不能突破消息栏。高度上限建议为消息视口的 60%，临时扩大查看不覆盖常用尺寸。拖动时使用直接反馈，不给拖动位置叠加缓动；双击复位恢复 3 行默认值。

历史详情明确列出输入、输出、状态、工作目录及可获取的耗时/退出码。当前日志若未保留退出码或 stderr 分流，展示“未记录”或“合并输出”，不能根据文本推测。超长结果分页/按需加载，截断必须有说明；点击历史命令不触发重跑。

### 4.4 推理窗口：真实进度与柔和显示

现有打字器已按时间控制速度，不能仅重复加入另一层逐字定时器。建议保留其积压追赶机制，将字符串切分调整为完整字素，避免中文标点、emoji 或组合字符断裂。

新增尾部短文本片段 100–160ms 的透明度过渡，仅对新增尾部执行；稳定历史文本不重复动画、不拆成成千上万个逐字 DOM。显示落后真实事件流的目标上限为 250ms，积压超限或窗口从后台恢复时直接追齐。没有待显示文本时停止空转 rAF。

展开/收起使用保留挂载的容器与实测高度过渡，建议 160–220ms；结束先显示最后内容，再折叠，不能因卸载丢掉尾部。动画需遵从系统减少动态效果设置，此时直接展示文本和切换高度。

默认约 3 行，上限建议 `min(20vh, 180px)`；手动调整上限为消息视口的 60%。尺寸按窗口全局记忆、会话间复用，窗口缩小时夹取到可用空间，不改变原偏好。沿用终端的尺寸校验思路，避免多个不一致的拖拽实现。

默认追随最新内容；用户上滚后暂停跟随并显示“回到最新”，点击或滚回底部恢复。内部滚动和外部会话滚动分别管理。只显示模型实际提供的可展示推理内容；无数据不显示占位过程。

## 5. 文件附件、链接与改动审阅

### 5.1 文件拖放

当前问题的源码原因明确：普通文件被 `image/*` 过滤。需要扩展附件模型，而不只是删除过滤条件。

建议使用图片附件和文件引用两种类型：图片沿用现有编码通道；源码、日志、Markdown、PDF 等先生成带名称、类型、大小和路径的附件标签。普通文件路径通过受限 preload 能力交给主进程校验；文件内容只能走明确的读取流程，不能把任意文件都按图片 base64 发送。

文本文件首期支持模型按路径读取；图片仍走图像输入。PDF 等文件可以引用，但只有后端确实具备解析工具时才标示“可读取内容”，否则提示格式能力限制。文件夹首期作为目录引用，不递归读入或自动上传全部内容。

用户拖入工作区外文件时，为该次附件生成有限范围授权记录。普通文本中的任意绝对路径不能因此获得相同权限。标签支持移除、重复文件去重及失败重试；只有附件没有文字时也能发送。纯文本拖入维持文本插入体验。

建议首期最多 20 个附件、图片合计 20MB；阈值属于产品默认建议，实施时与实际模型限制取较小值。大型文本采用按需读取，避免一次把整个文件塞进上下文。上传或模型读取前，用户必须能看见附件列表。

### 5.2 统一地址打开

建立一个 LinkRouter，覆盖 Markdown 链接、普通网页地址，以及可明确识别的文件地址。识别只作用于完整文本节点，避免改写代码块、代码示例和流式输出中的半截路径。

| 地址 | 打开行为 |
| --- | --- |
| `https://`、`http://` | 通过现有浏览器状态动作展开右栏并打开标签页；菜单提供外部浏览器选项 |
| 项目内相对路径 | 按该条消息所属会话 cwd 解析，不使用后来切换的项目 |
| Windows 绝对路径、带空格路径 | 主进程校验后进入只读文件预览 |
| `path:42` 等行号 | 分离盘符与行号；打开后滚到目标行 |
| 不存在的文件 | 显示文件不存在，并保留复制路径入口 |
| 非法协议/可执行文件 | 拒绝危险协议；可执行文件不能通过消息链接直接运行 |

安全检查应覆盖 `javascript:`、`data:`、路径穿越、符号链接/junction 逃逸与 IPC 发送方。现有 `files.ts` 的字符串路径边界不能作为 realpath 安全校验的替代。文件预览中的 HTML 和 Markdown 不执行脚本，网页跳转始终经过统一入口。

右侧新增“文件预览”视图，与浏览器/子代理详情复用同一详情区域，关闭后恢复原浏览器状态。原生 `WebContentsView` 位于 DOM 之上，切换时必须同步隐藏或调整原生视图，不能只盖一个 CSS 面板。

### 5.3 查看具体文件改动

现有 edit 数据能展示替换片段，但并不等价于完整文件 diff；write 也可能覆盖旧文件，不能一律当成新增。

分两步实施：

1. **可查看阶段**：所有 edit/write 历史调用可点击；展示工具输入中的前后片段或提交内容，并明确“替换片段”“写入内容”和执行结果。失败调用标明“未成功应用”。
2. **可靠差异阶段**：在受支持写入工具执行前后保存有限大小快照和哈希，按会话/回合/工具调用关联；显示逐行差异、文件状态与新增删除行数。并发写入校验前置哈希，冲突时不把组合变化错误归给单个调用。

对 shell 或第三方工具产生的任意改动，首期只能展示项目 Git 工作区差异，并明确它可能包含用户和其他任务改动；非 Git 项目需要快照支持。不能将当前工作区 diff 冒充历史某次操作的 diff。旧会话没有前置快照时如实退化，不反向编造。

建议预览单文件文本上限 2MB，超限或二进制文件显示元信息并提供打开位置。快照属于用户数据，与会话删除/恢复策略保持一致，不进入仓库提交；默认不保存额外的密钥类文件副本。

## 6. 模型提问：保留聊天阅读空间

普通 `select` / `input` / `editor` / `confirm` 请求改为输入区上方的独立问题面板，继续使用现有 request id 与 `extension_ui_response` 协议。

```text
需要你选择 · 1/2                                      收起
这次的文件预览应该采用哪种方式？
○ 右侧面板   ○ 独立窗口
[补充说明……]
                                      [取消] [提交回答]
```

面板宽度跟随消息区，默认最多约 200px，高度不超过消息视口的 35%；长问题内部滚动。收起后保留“有 1 个问题待回答”提示与草稿，历史消息和右侧详情仍可操作。

使用普通区域语义而非 `aria-modal=true`；取消全局焦点圈定，提供“回到待回答问题”快捷入口。提问到达不强抢用户正在编辑的焦点。Enter 只在面板按钮或指定输入行为内提交，中文输入法组合期间不提交。

维持请求队列，草稿按会话与 request id 保存；提交防重、超时失效、切会话隔离、进程退出清理。仅收起面板不会发送取消或默认答案。

安全敏感确认应新增明确的请求分类，不根据问题措辞推断；未分类的旧 confirm 默认保持需明确同意的行为。自主模式不能自动替用户授予浏览器/文件系统权限。真正的删除确认、设置对话框仍按各自模态逻辑处理。

`dialog` 探针需同步调整：普通问题改测“能切换焦点阅读历史”，设置/删除等真正模态层继续测焦点圈定，不能沿用旧断言把新交互判成错误。

## 7. 任务、额度、上下文与缓存

### 7.1 任务高亮

当前有任务行高亮、复选框、状态文字多个相邻元素。建议布局固定为“状态槽 16px / 文本 minmax(0,1fr) / 状态说明”，运行高亮使用行内背景或内侧 2px 标记，给状态槽至少 8px 间距，不使用外扩轮廓穿过复选框。

`blocked` 明确显示警示图标与“受阻”；pending、running、done 使用不同语义。只有数据明确标记受阻时才显示，不把长时间运行推断为受阻。保持现有任务总数口径：完成数 / 全部数，受阻仍计入总数，可附加“1 项受阻”。没有第二个可靠来源时不虚构协议对账。

重叠问题属于待真实窗口复现项；检查宽窗口、窄右栏、长中文任务名、三档密度及系统缩放后才能结项。

### 7.2 Command Code 额度

严格按用户提出的“已用 / 未用”口径布局，但显式加“剩余”标签，避免斜杠被误解为已用/总额。以下数字仅为布局示例，不是账户查询结果。

```text
commandcode   已用 $35.41

五小时  已用 25.0%              $3.50 / 剩余 $10.50
████░░░░░░░░░░░░
重置于 2时18分后

周额度  已用 60.0%              $21.00 / 剩余 $14.00
█████████░░░░░░░
重置于 3天4时12分后

月额度  已用 50.6%              $35.41 / 剩余 $34.59
████████░░░░░░░░
重置于 2026/10/01 13:56:30
```

主值“已用”定义为本月已用，不能继续取当前最紧张窗口的 used；标题辅助说明或悬停写明“本月已用”。每个窗口保持一组数字、一条细进度条、一条次级重置说明，移除重复卡片边框。

当前 `quota.ts` 从 credits 接口读取 5 小时/周窗口，月额度总量由 `weekly.cap × 2` 推算。代码注释中的历史观察不能保证现在每个套餐都成立。后续实现必须优先获取明确月额度字段或已验证套餐定义；若只能推算，明确标示“月度上限推算”，没有可靠依据则显示已用金额，比例和剩余显示“—”。

为数据增加来源/确定性标记，UI 不得将推算值伪装为精确官方额度。五小时和周重置按本地时区倒计时，月重置显示年月日与秒，并可查看时区。到点后显示“待刷新”并重新查询，不能本地自动归零。超过 100% 时文字显示真实比例，进度条仅夹取宽度，剩余金额不出现负数。

查询失败保留旧快照并注明更新时间；空值不能显示成 0。切换 provider 后防止上一个请求覆盖新账户视图。刷新与详情放在标题区或二级菜单，其他 provider 继续沿用其原有金额/百分比语义。

### 7.3 上下文区块

默认仅展示“上下文 42%”“84k / 200k”和一条细进度条，次级文字显示压缩状态；数字只是示例。阈值、保留量、预留 token 等调节项移入“详情”。

继续保留当前对压缩后 `tokens=null` 的处理，显示“更新中”而不是 0%。上下文表示当前会话占用，不能用累计 token 消耗代替。预算和 provider 额度与上下文分别呈现。

### 7.4 缓存命中率

保留当前归一化口径 `cacheRead / (input + cacheRead)`，先确认各 provider 在 normalize 后符合这一含义，不把 cacheWrite 当作命中。

显示规则建议：有数据时显示两位小数；0 分母显示“—”；只有原始比例等于 100% 才显示 `100%`，否则按两位小数截断，确保 99.999% 不变成 100%。悬停展示原始缓存读取与输入 token，说明这是按 provider 报告值计算。流式期间没有用量时显示“待结算”，不拿旧轮次比例代替。

### 8.3 前端如何预览

主对话内显示一组紧凑子任务行：名称、当前状态、最新一行活动、耗时。点击后在右侧打开“子代理详情”，包含任务说明、实际输出、工具记录与文件改动入口；不切走主会话。

```text
子任务 · 2 运行 / 1 完成
● 检查附件流程     正在读取 Composer.tsx       18s
● 检查浏览器权限   正在检查权限处理            11s

```

右侧预览复用现有消息与工具详情组件，提供“回到最新”“停止”“继续此子任务”。同时展示运行过程与结果；若子代理启动了网页预览，则提供经校验的预览地址入口，使用现有内部浏览器，不默认截取整个桌面或虚构运行画面。

主界面关闭预览不停止任务。停止父任务应明确是否停止其仍在运行的子任务，默认一并停止并等待确认退出；关闭应用时展示仍运行任务的处理策略。重新打开后只有能重新连接且验证存活的进程才显示运行，否则标记中断。

### 8.4 数据与并行边界

建议新增 `SubagentRun`，包含 `id / parentSessionId / parentTurnId / parentToolCallId / childSessionId / status / model / cwd / startedAt / endedAt / latestActivity / transcriptRef / error`；事件带 run id、递增序号和时间，支持去重、断点续读与有界缓存。

运行数据经主进程汇总、IPC 增量推送到 store，按单个 run 订阅，避免每个 token 重建整份主会话。持久化记录与已有分支会话关联，但“分支”不能直接等同“正在运行的子代理”。

建议首期默认最多 2 个并发子代理、嵌套深度 1，提供数量/耗时上限。只读检查可以共享 cwd；写入任务优先使用独立 Git worktree，非 Git 项目采用独立副本或串行写入。子任务完成与合并改动是不同状态，不因完成自动覆盖主工作区。费用缺失时显示未知，避免父工具汇总和子会话用量重复计费。

若支持转发子任务提问，必须带 run id 和原始 request id，回答只回到对应子进程。子代理只获得所需浏览器/文件能力，不继承无范围的桌面桥接凭证。

## 9. 内部浏览器安全设计

### 9.1 当前可以确认什么

`src/main/browser.ts` 的远程网页 `WebContentsView` 已设置：

```text
sandbox: true
contextIsolation: true
nodeIntegration: false
partition: persist:yan-browser
```

已有导航协议检查、新窗口拦截、本地 loopback 随机端口与 token。`BrowserPolicy.ts` 对删除、支付、发送等关键词进行动作拦截，但它只是启发式提示，不能保证识别全部副作用。

主应用窗口在 `index.ts` 中仍为 `sandbox:false`，虽然启用了 contextIsolation 并关闭 Node 集成。这与远程网页视图是两个边界，需要单独评估 preload 依赖后再迁移。

因此准确结论是：**内置远程网页已经有 Chromium/Electron 进程沙盒，但整个 agent 没有因此获得命令执行沙盒。** 独立浏览器分区用于隔离数据，也不等于无痕模式或项目级隔离。pi 执行本地命令、读取文件的权限必须另行管理。

### 9.2 优化项

1. 对浏览器分区设置明确的 permission check/request handler。摄像头、麦克风、定位、通知、剪贴板等按来源与用途管理，默认拒绝未授权请求，拒绝状态可恢复查看。依据：[Electron Security](https://www.electronjs.org/docs/latest/tutorial/security)、[Session API](https://www.electronjs.org/docs/latest/api/session)。
2. 给代理动作增加结构化权限范围，例如只观察、填写、提交；明确动作与当前站点、当前目标的授权记录。关键词检查保留为辅助，普通“自主模式”不跳过敏感授权。
3. 校验 IPC 来源与参数，本地桥接验证方法、内容类型、请求体大小和 token；能力凭证不得进入网页、模型普通输出或日志。
4. 保留编码必需的 localhost 页面预览，但限定显式开启的项目开发端口；页面不能访问 Yan 管理桥或任意本地服务。仅做顶层 URL 检查不足以防子资源/重定向访问，需要网络请求层检查、重定向重验和 DNS/地址边界设计。
5. 下载界面显示来源和状态，不下载后自动执行；外部协议经显式用户操作打开。Cookie/页面存储导入只在用户发起时执行，限定所选来源与目标，提供清理站点数据入口。
6. 分批评估主窗口 sandbox 迁移；先列出 preload 所需能力，以最小 IPC 替代依赖，再测试文件、登录、拖放与浏览器布局。不能只改布尔值就宣称完成。

进程沙盒原理依据：[Electron Process Sandboxing](https://www.electronjs.org/docs/latest/tutorial/sandbox)。命令层的文件系统/网络限制可以作为后续独立功能评估；本次浏览器优化不得对用户宣传为“本地命令完全安全”。

## 15. 补充：删除会话提示 UI 修复设计

本节依据用户追加截图及 `Rail.tsx`、`composer.css`、`dialog.css` 的源码检查。截图是当前视觉问题的证据；以下仍是方案，没有执行真实删除或改动运行代码。

### 15.1 已定位的问题

1. **错误使用按钮样式**：删除成功分支的“撤销删除”使用 `className="send"`，会应用输入框发送按钮的专用尺寸和圆形外观，导致四个中文字换行并挤在圆形按钮里。不能通过缩小文字修复，应改用内容自适应的普通动作按钮。
2. **标题与状态不一致**：正文已说明会话移入回收站，标题仍为“删除这个会话”，成功后还使用警示图标，会让用户误以为仍待确认。
3. **恢复失败没有可见反馈**：`restore()` 会设置 `error`，但 `undoToken` 对应的成功分支没有渲染错误区域，用户可能只看到按钮重新可用。
4. **删除成功后继续遮挡**：已经执行完的可逆操作仍保持全局模态遮罩，要求再点一次“确定”；与保持任务流畅的设计目标不符。

### 15.2 交互分成确认、进行、成功、失败

| 状态 | 界面 | 操作 |
| --- | --- | --- |
| 删除前 | 小型确认框，标题“将会话移入回收站？”；显示会话名、实际影响的分支数 | 取消 / 移入回收站 |
| 删除中 | 原位置显示“正在移入回收站…” | 防重复提交；明确进行状态 |
| 删除成功 | 关闭模态框，在左栏或主界面底部显示轻量通知“已移入回收站” | 撤销 / 关闭通知 |
| 删除失败 | 确认框内显示具体失败原因 | 保留取消与重试 |
| 正在撤销 | 通知变为“正在恢复…” | 暂时禁用重复撤销 |
| 撤销失败 | 通知保留错误和可重试入口 | 不把失败当恢复成功 |
| 撤销成功 | “会话已恢复”并刷新对应树节点 | 可定位恢复会话，焦点回到合理位置 |

当前输入完整标题的确认条件先保留，尤其删除有分支的父会话时不能顺手取消。普通会话是否放宽确认可以后单独评审。删除正文同时说明影响范围和“本次运行内可撤销”，不暗示现有系统具备跨重启恢复入口。

后端目前会递归移动关联会话，并通过本次进程内的 token 撤销；本次 UI 设计沿用这一能力。成功通知关闭后，撤销记录应保存在运行期 store 的轻量记录区，提供“最近移入回收站”入口，避免关闭通知等于永久失去当前可用的撤销操作。它只列本次运行记录，重启后不展示失效按钮。

删除执行结果与列表刷新结果分别处理：文件已移动但列表刷新失败时，应提示“已移入回收站，列表刷新失败”，保留撤销 token，不能再次执行删除。主进程请求异常也需统一恢复 busy 状态并显示错误。恢复部分成功的情况由后端报告准确状态，避免无限重试已恢复路径。

### 15.3 视觉规范

确认框建议宽度 `min(420px, viewport - 32px)`；正文自然换行，会话长标题最多预览两行，另有完整文本查看。按钮使用普通小圆角矩形，推荐高度 30–32px，按内容加水平 padding，文字不换行；不得再借用 `.send`。

底部按钮靠右排列，取消为次要动作，删除用语义危险样式；成功通知的撤销是普通主要动作，不使用危险红色。移除删除完成后的大块正文底色与冗余警示图标，深浅色均继承现有令牌。

确认框维持焦点圈定、Esc 取消和焦点恢复；成功通知不圈定焦点、用状态播报，不打断用户输入。若原会话行已消失，焦点回到下一条会话或新建会话入口。浏览器原生视图打开时，确认框必须实际可见；成功通知则放在原生视图不会覆盖的区域。

### 15.4 实施和验收

本项提到阶段 1 的优先修复：先去掉错误 `.send`、切换正确标题、补足错误状态；随后完成非模态成功通知与运行期撤销入口。涉及 `Rail.tsx`、`rail.css`、`dialog.css`、i18n、store，以及必要的删除响应状态整理。

验收覆盖：删除无分支会话、删除父会话的范围提示、活动会话保护、删除失败、撤销失败、重复点击、关闭通知后撤销、长标题、中英文、深浅色、125%/150% 缩放。真实删除测试只用专门创建的测试会话，不操作用户真实历史。截图需证明“撤销”按钮文字完整、标题匹配状态、浏览器不遮挡；源码检查不能代替最终视觉验收。

## 16. 补充：文件树重新设计

### 16.1 当前基础与需要改变的行为

`FileTree.tsx` 已实现逐层懒加载、目录开合、目录/文件图标、隐藏项开关、当前展开目录刷新、@路径插入；无需从零重写。当前单击文件只会修改输入框，缺少“先看看内容”的自然入口，与本次代码审阅、文件预览需求不一致。

当前标题数字是已加载目录中的条目累加，包含目录且受展开程度影响，不能当作整个项目文件数量。建议移除常驻数字，或在详情中明确写“已加载 N 项”。隐藏项开关目前使用太阳/月亮图标，容易与主题切换混淆，改为可见性语义图标或菜单项。

### 16.2 推荐布局

```text
文件                              [查找] [刷新] [更多]
pi-desktop
  ▾ src
    ▾ renderer
      ▸ components
        App.tsx                         M    [+]
        main.tsx                             [+]
  ▸ resources
    package.json                             [+]

选中文件 → 右侧详情区展示只读内容与行号
[+] 或“加入上下文” → 将文件加入当前输入草稿
```

示意中的 `M` 仅在取得真实 Git 状态时显示；没有 Git 状态接口时不绘制。文件树仍在右栏工具区，预览使用第 5 节统一详情区域；树保持可访问，不因预览把整个项目导航挤走。窄窗口可以进入临时详情页并提供“返回文件树”，恢复滚动位置。

每行建议标准密度 26px、紧凑 22px、舒适 30px，最终以字体实测调整。固定箭头与图标槽位，文件与目录名称起始线一致；深层目录每级约 12px 缩进，深度过大时提供面包屑定位，不持续缩小字号。选中行用轻背景，悬停动作在键盘聚焦时同样可见，文件名保留扩展名并能查看完整路径。

### 16.3 明确点击、引用与键盘规则

- 目录箭头或目录行：展开/收起；不向输入框插入文字。
- 单击文件：选中并只读预览；不改变草稿，不执行文件。
- 行尾“加入上下文”按钮：加入当前会话草稿，显示短暂反馈；已加入时显示选中状态，可移除。
- 拖入输入框：复用新的附件引用通道，支持带空格和中文路径；拖拽文件树行与右栏模块排序使用不同拖动类型，避免冲突。
- 右键菜单：预览、加入上下文、复制相对路径、复制完整路径、在资源管理器中显示；首期不加入重命名、删除或移动项目文件。
- 键盘：上下选择可见行，右箭头展开目录，左箭头折叠或回到父目录，Enter 预览文件，独立快捷操作加入上下文。采用 tree/treeitem 语义与单一游走焦点，不让每行多个按钮造成大量 Tab 停靠点。

这会改变当前“单击插入 @路径”的行为，应同步修改提示文字与现有 `fs` 探针；不在相同点击上同时预览和插入。文件预览、消息中的文件链接、文件改动入口共用同一个文件身份与打开协议。

### 16.4 查找、隐藏项与刷新

首期查找区分两种范围：快速过滤已加载节点时明确写“在已加载项目中筛选”；需要整个项目查找文件时走有结果上限、可取消的主进程文件名索引/检索接口，不为了搜索而递归挂载全部树节点。项目搜索默认跳过大型依赖目录，可在详情中配置范围。

隐藏项放入更多菜单：“显示隐藏文件”“显示依赖和版本目录”。隐藏项可列出但大型目录仍按现有边界处理；不能因为开启开关就预扫 node_modules。空文件夹、无权限、路径失效、读取中、结果截断必须是不同状态，各有局部提示。

继续逐层读取和按需渲染。手动刷新只更新已展开目录；受支持的写入工具完成后通知相关父目录失效，再局部刷新。后台文件监听作为后续可选优化，需合并事件并限制目录范围，不能逐 token 触发刷新。

项目切换时给读取请求绑定 cwd/projectId 和代次，旧项目请求返回后直接丢弃。当前 `load()` 回调没有请求代次，异步结果存在切项目后写入缓存的风险，需测试并补齐；清空缓存时同时处理 loading 状态，避免根目录不重新加载。

目录展开、选中与滚动状态建议按项目保存在当前窗口内存中，切回来恢复；隐藏项可作为全局外观偏好落盘，默认保持旧行为。当前组件的 showHidden 是临时状态，改变记忆范围需要显式迁移默认值。

### 16.5 数据与安全边界

文件树只读取所属项目；项目外附件通过第 5 节附件授权管理，不把外部文件直接挂入整棵目录树。所有预览和“显示位置”调用在主进程校验真实路径、授权范围和发送方，不能信任渲染端传入的绝对路径。

新增预览数据建议包含 `projectId / relativePath / resolvedPath / mimeType / size / modifiedAt / textOrPreviewRef / truncated / error`。前端根据文件大小和类型选择文本、图片或不支持提示；不把二进制文件当文本解码，不加载未清理的 SVG/HTML 脚本。

### 16.6 排期与验收

基础交互放到阶段 1，与文件附件和统一预览一起实现；视觉层级、键盘树和菜单在阶段 2 完成；可选 Git 状态与改动定位随阶段 4 接入。无需等待子代理功能。

验收覆盖：真实项目单击预览不改草稿、加入上下文可发送、中文空格路径、目录拖放、键盘操作、文件新建/删除后的刷新、快速切换项目、无权限/空目录/截断目录、深层路径、窄右栏，以及内部浏览器打开时的预览布局。保留懒加载性能，不把“节点可以列出来”视为完整文件树体验验收。
