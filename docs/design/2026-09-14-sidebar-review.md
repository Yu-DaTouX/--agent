# 2026-09-14 左右栏方案评审记录

本文对照了桌面上的 `RIGHT-PANEL.md`、`左栏新方案以及其他小问题-gpt6修订版.txt`，以及当前工作区中的未提交改动。两份文档按“待评审的产品方案”处理；文档中的目标并不自动等同于已经授权或已经完成的实现。本文只记录现状、差异和需要后续决定的事项。

## 当前已接入的方向

- 左栏已按项目工作目录分组，会话按 `parentSession` 递归显示为树；默认折叠分支，搜索命中时保留祖先并展开路径。
- 已加入置顶、项目归档显示切换、项目重命名入口、复制/显示路径、当前会话、运行中、等待输入、错误/中断和未读完成结果等 UI 状态。项目折叠、分支展开、置顶、归档和未读状态使用 `localStorage` 保存。
- 左栏已有紧凑模式入口（砚、搜索、新对话、设置），宽度常量已改为默认 260px、可调整范围 210–420px；拖拽结束才写入设置，拖到临界值可收起。右栏浏览器高度会根据剩余空间夹取，额度字段和会话标题采用单行省略，文件树增加了展开箭头、文件图标和更紧凑的行高。
- 消息正文使用 Windows UI 字体、较紧的中文字距和正常粗体描边；代码、路径、终端等区域保留等宽字距。
- 浏览器 Cookie 已有明确方向的手动复制：活动的 Chrome 与另一侧受管浏览器通过 CDP 互拷 Cookie。界面文案已说明这不复制设置、localStorage 或删除状态，也不保证所有站点登录可迁移。
- 文件型 Chrome profile 导入现在避开正在运行的真实 Chrome；复制目标固定使用受管 profile 的 `Default`，不会自动覆盖已有受管 profile。该导入路径的“文件已复制”也不应被表述为“已验证登录”。

## 与左栏方案的差异和未完成项

当前数据模型仍主要是“按 cwd 分组的会话列表”，不是具有稳定 ID、分组关系和独立生命周期的项目实体。项目名称来自设置中的映射，项目列表也会由最近工作目录补出。因此方案中的“项目 → 主会话 → 分支”视觉层级已部分呈现，但项目移动到分组、编辑目录、恢复原分组、项目级归档页面等完整实体流程尚未实现。

会话菜单目前支持置顶、重命名、显示路径、复制路径和已有的会话操作；删除含子分支的会话与当前会话会被禁用。叶会话删除改为应用内确认卡片：必须输入完整标题，文件会原子移动到 `砚数据/trash/sessions`，并可在本次应用运行中立即撤销。仍未实现的是“停止正在运行的会话后删除”和递归处理分支子树；因此不能把现有叶会话删除流程当作完整的分支删除流程。

搜索已能把命中项的父级带回结果，但清空搜索后恢复搜索前展开状态、滚动到目标并聚焦目标的完整交互仍需核对。置顶区当前按会话路径单独渲染，分支子树不会在该区展开；深于三层的“显示更多分支”也没有专门的折叠入口。

方案要求的运行中、等待输入、未读和错误状态优先级已有代码表达，但状态来源仍集中在当前会话 store，尚未证明能覆盖所有后台任务或多个会话并行变化。日常模式只显示不可选择的入口，模式行为尚未接入。

方案中建议使用 Electron `app.getPath("userData")` 作为统一数据根目录；当前 `src/main/paths.ts` 有意保留便携版“可执行文件同级 `砚数据`”，非便携版则由 `YAN_*` 覆盖或落到 `~/.pi/agent/yan` 的路径约定。没有做数据迁移，也不应在评审中声称已经迁移到 `AppData\\Roaming\\Yan`。升级保留旧数据的行为需要另行验收。

## 右栏方案的差异和未完成项

浏览器高度夹取解决了明显的数值越界方向，并为工具区预留空间。已用原生 Electron 窗口截图检查 940×620 窄窗口：左栏、会话树、浏览器和工具区能够同时显示，截图保存在 `docs/design/preview/sidebar-review-940x620.png`。更复杂的长会话、极矮窗口和各工具区组合仍需按产品验收标准复核。

Cookie 复制只覆盖“当前活动浏览器 → 另一侧受管浏览器”的手动方向。它不等于双向持续同步，不同步浏览器设置、localStorage、历史删除或其他 profile 状态，也不保证站点的绑定密钥、设备校验和全部登录态都能迁移。普通 Chrome 文件导入同样没有经过“复制后已登录”的验证；Cookie 文件被 Chrome 占用时，代码会跳过 Cookie 与解密密钥并报告原因。

文件树已更直观，但隐藏文件开关、目录排序、路径呈现和大目录性能仍应按产品验收标准确认。额度提示已设置单行省略，需在最窄宽度和不同语言下检查是否仍会遮挡操作按钮。

为缓解大上下文下左右栏折叠/展开卡顿，评审样式关闭了 workspace 的宽度过渡；这只是降低重排压力的实现选择，尚未由真实 Electron 窗口证明卡顿消失。消息字距和粗体样式也只完成了代码层调整，视觉效果仍需启动应用检查。

## 当前评审结论

当前改动可以作为左栏树形导航、紧凑布局和右栏浏览器交互的第一轮适配，但仍属于部分实现。最重要的产品缺口是项目实体/分组管理、会话与分支子树删除安全流程，以及浏览器设置和登录态同步的边界；最重要的验证缺口是实际 Electron 窗口中的布局、性能和登录结果。后续报告应区分“代码已具备入口”“行为已验证”和“方案仍待实现”，避免把静态检查或文案改动当成完成凭据。
