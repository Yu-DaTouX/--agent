# 当前 UI 结构与优化方案

## 1. 评审范围与结论

本方案基于当前渲染层源码、`2026-09-14-sidebar-review.md` 评审记录及仓库内预览图。未启动窗口进行本轮实测，也未修改实现代码；带模拟标记的预览图仅作视觉参考。以下区分源码可确认的问题与需要实机验证的建议。

**总体方向：保留三栏工作台，不推倒重做。优先完成信息减负、布局规则统一和样式收敛，再优化视觉细节。**

技术栈：Electron + React 19 + Zustand + CSS + virtua。

- 深浅主题、国际化、减少动态效果支持。

## 3. P0：结构性问题

### 3.1 收敛多轮样式覆盖

**已确认现状**

`App.tsx` 中的样式加载顺序为：

```text
tokens → app → stage1 → stage2 → redesign
→ motion → settings → electron → highlight → sidebar-review
```

其中 `redesign.css` 为 4733 行，`motion.css` 为 1363 行。最终效果依赖多个文件的覆盖顺序。最新评审样式重新定义了侧栏宽度、收起状态、正文字体和浏览器布局。

部分注释已落后于实现：例如 `App.tsx` 仍有左栏收起为 0 宽的描述，而最新紧凑模式保留 48px 快捷轨。

**优化方案**

1. 按 `layout / rail / chat / composer / tools / browser` 归并最终有效样式。
2. 将最新补丁逐步迁回所属模块，淘汰 `stage*` 和评审补丁文件。
3. 统一布局、间距、字号、层级、动效令牌。
4. 清理与当前实现冲突的注释，历史决策放入设计记录。
5. 每次迁移一个区域，以截图和交互回归验证，不直接批量删除旧规则。

**验收**

- 同一布局规则有明确归属，不再依靠新增末尾补丁修正。
- 深浅主题、左右栏收放和浏览器分屏不出现视觉回归。
- 布局文档、令牌和最终计算样式一致。

### 3.2 以主任务空间为核心制定窄屏规则

**已确认现状**

最新窄屏规则将展开的左右栏分别限制到约 210px、190px；浏览器和工具同时打开时共享右栏高度。上述规则的完整可用性仍需在不同尺寸及缩放下验证。

**优化方案**

- 用对话区最小可用宽度决定布局，避免无限压缩三栏。
- 宽屏保留三栏；中等宽度优先紧凑左轨；极窄窗口提供显式“专注对话”模式。
- 浏览器提供“独占右栏 / 与工具分屏”切换，保留独立开关。
- 窗口临时缩小时只夹取实际显示尺寸，不改写用户保存的面板宽度。
- 不恢复鼠标悬停自动展开，不让面板开关随收放漂移。

具体断点与最小宽度应由原生窗口测量确定，不在本方案中直接作为最终实现值。

**验收**

- 窄窗口下输入、发送、停止按钮可达。
- 浏览器、工具库和工具区同时打开时不越界。
- 恢复宽窗口后，用户保存的布局可恢复。

### 3.3 修复快捷键与弹窗焦点一致性

**已确认现状**

- `App.tsx` 全局拦截 `Shift+Tab` 切换思考强度，会与表单反向焦点导航冲突。
- `Settings.tsx` 有弹窗语义和 Esc 关闭，但组件内未见焦点圈定及关闭后的焦点恢复。
- “回到底部”按钮仅显示箭头，缺少明确的可访问名称。

**优化方案**

- 模型、思考快捷键限定在对话输入上下文；弹窗打开时暂停对应全局处理。
- 同时核对主进程快捷键分发，避免仅修改渲染端后仍被上游拦截。
- 建立统一 Dialog 基础组件，处理初始焦点、焦点圈定、Esc 和焦点恢复。
- 为纯图标按钮补齐名称，保留清晰的键盘焦点样式。

**验收**

- Tab / Shift+Tab 可完整遍历设置控件，不意外切换模型或思考强度。
- 弹窗关闭后焦点回到打开它的控件。
- 图标按钮可被辅助技术正确识别。

## 4. P1：日常使用体验

### 4.1 左侧导航

- 固定搜索和新对话入口。
- 项目和分支采用渐进展开，避免深树挤压会话标题。
- 清空搜索后恢复搜索前的展开状态、滚动位置和焦点。
- 搜索跳转后明确高亮目标；状态图标同时提供文字提示。
- 后台会话状态来源需单独验证，不把当前会话状态等同于所有会话状态。

### 4.2 消息、推理与工具结果

- 最终回答作为主视觉，推理和工具过程作为次级信息。
- 成功工具调用默认摘要，错误结果保留明显入口。
- 推理和终端默认内容自适应，并设置高度上限。
- 用户主动调整大小后再记忆尺寸，避免短内容默认占用大面积空白。
- 保留展开详情、复制和定位能力，不以隐藏过程为代价换取简洁。

### 4.3 输入区

**当前问题：输入框展开后 Enter 的语义会变化。**

建议输入框高度只影响布局，不影响发送行为：

- 将发送快捷键设为明确的用户配置。
- 在输入区持续显示当前发送规则。
- 区分空闲、生成中、排队、等待用户和错误状态。
- 队列内容主要保留在输入区，工具栏侧重投递策略，减少重复展示。

### 4.4 工具栏信息层级

建议默认优先顺序：

```text
任务 → 上下文 → 文件
额度 / 队列策略 / 日志 / 扩展 / 操作按需展开
```

- 保留用户自定义排序和显隐设置，不覆盖既有选择。
- 新默认顺序仅面向无自定义配置的用户，或由用户主动恢复默认。
- 空分区继续避免占位；有错误时给出入口，不强行打断阅读。
- 额度和上下文数值显示简明，详细口径放在展开内容中。

### 4.5 任务状态语义

**已确认现状：任务面板把第一个未完成任务直接标记为正在进行。**

建议后续引入明确状态：

```text
pending / running / done / blocked
```

- 尚未开始的任务不持续显示执行动画。
- 只有明确运行中的任务显示 spinner。
- 兼容现有仅有 `done` 字段的数据；不能仅改样式就宣称状态模型已完成。
- 状态模型涉及共享类型和工具协议，应独立评估，避免与纯 UI 样式改造混在一起。

## 5. P2：视觉与性能收敛

### 5.1 视觉

- 保留正文非等宽、代码及路径等宽的方向。
- 增加“紧凑 / 舒适”密度，而不只依赖整窗缩放。
- 减少重复边框和装饰，使用背景、间距和字体建立层级。
- 强调色主要用于当前会话、当前任务和主操作。
- 减少多个区域同时呼吸或扫光，保留必要的执行反馈。
- 延续 reduced-motion 支持，并覆盖新增交互。

### 5.2 性能与滚动

已有回合虚拟化和 `TurnView memo`，无需重复建设。重点验证：

1. 流式更新是否导致历史回合重新分组或无效渲染。
2. 动态推理和工具内容展开时是否导致阅读位置跳动。
3. 左右栏收放时长消息重排的耗时。
4. 普通列表和虚拟列表的导航行为是否一致。

源码中普通列表滚动会更新 `scrollProgress`，虚拟列表回调当前只更新贴底状态，需要核验长会话导航进度是否一致。

性能优化应先测量，再决定是否需要增量分组、状态订阅细化或渲染隔离。

## 6. 推荐代码组织

以下为目标方向，不要求一次迁移完成：

```text
components/
├─ shell/               应用布局、标题栏、统一弹窗
├─ rail/                项目、会话树、搜索、菜单
├─ chat/
│  ├─ ConversationViewport
│  ├─ TurnView
│  ├─ Composer
│  └─ ...
├─ toolbar/
│  ├─ RightPanel        仅负责布局与分区组织
│  ├─ sections/         任务、上下文、额度、队列等独立分区
│  └─ ...
├─ browser/
└─ settings/            独立设置页

hooks/                  滚动跟随、快捷键、主题同步等
state/                  按会话、布局、浏览器、设置等领域组织
styles/                 令牌、基础、布局和组件样式
```

拆分原则：

- `App.tsx` 主要负责组装，提取会话视口和滚动逻辑。
- `RightPanel.tsx` 保留布局与排序，各工具分区独立。
- `Composer.tsx` 拆出附件、命令菜单、队列等职责。
- store 先按领域整理动作和选择器，不为拆文件而改变持久化语义。
- 不因单纯行数较多而重写已稳定的业务逻辑。

## 附录：实施进展

> 本节由实施过程追加，不属于原方案正文。原正文的结论与清单未改动。

### P0-3 快捷键与弹窗一致性（已完成）

| 原方案要求 | 落地方式 |
| --- | --- |
| 快捷键限定作用域、弹窗打开时暂停全局处理 | 新增**模态栈**（`lib/modalLayer.ts`）；栈非空时通过 `setHotkeyGuard` 上报主进程，`before-input-event` 不再拦 Shift+Tab / Ctrl+P。渲染端兜底监听同样放行——**两条路都暂停才算暂停**（只改渲染端会被主进程先吃掉）。缩放快捷键不受影响；窗口重载时守卫归零 |
| 核对主进程分发，避免只改渲染端 | 改了三处：主进程拦截、preload 通道、渲染端兜底 |
| 统一 Dialog 基座（初始焦点 / 圈定 / Esc / 恢复） | `useModalLayer` + `useFocusTrap`，接入 Settings、扩展对话框、首次引导、删除确认框 |
| 纯图标按钮补齐名称 | 「回到底部」补 `aria-label`；全量扫描确认无遗漏 |

实施中被探针抓出的两个真实缺陷（均已修）：

1. 多层模态叠加时，**下层**的焦点陷阱会把焦点从上层拽回来 —— 改为只有 `isTop` 接管。
2. `Settings` 用 `usePresence` 延迟挂载，陷阱 effect 在 `ref` 为 null 时静默失效 —— 改传已挂载状态。

验收对照：Tab/Shift+Tab 不触发模型或思考切换 ✓；关闭后焦点回到打开它的按钮 ✓；纯图标按钮可被辅助技术识别 ✓。新增 `dialog` live 场景（用**真实按键**，因为合成事件走不到主进程钩子）。

### P0-2 窄屏布局（已完成，实测驱动）

新增 `narrowscan` 场景（5 档窗口 × 4 种面板组合）取基线，据此发现并修复：

- **`app.css` 的 `@media (max-width:900px)` 是死代码**：`--w-rail` 被 `sidebar-review.css` 覆盖、`.rail{display:none}` 被 `redesign.css` 的 `.rail{display:flex}` 覆盖（同特异性、后加载）。它既没生效也没有意义，已删除并在原处留下说明。
- 窄屏规则改放到**真正生效的那一层**，并按实测倒推断点：`composer ≈ center - 73px`，要 ≥320px 则 `center ≥ 393px`。新增 900px 一档（左栏展开 ≤180px、右栏 ≤170px）。
- 用 `min()` 夹取**显示**宽度，不改写用户保存的 `--w-rail-user` / `--w-panel-user`。

最坏组合（视口 818px + 左栏展开 + 右栏开）：对话区 **345px → 395px**。

### P0-1 样式收敛（第一批完成，机制就绪）

- `scripts/css-inventory.mjs` → `docs/design/CSS-归属表.md`：量化「谁定义了什么、谁覆盖了谁」。当前 14 个文件 / 8698 行 / 1156 个唯一选择器，其中 103 个被多个文件定义。
- 原 `sidebar-review.css`（最新评审补丁）按模块拆为 `layout / rail / chat / tools / browser`，**放在加载链最末**，层叠结果不变。
- `scripts/css-split-check.mjs`：证明「拆分是等价重构」（按属性最终值比对）。
- `scripts/css-migrate.mjs` + `scripts/css-layer-check.mjs`：从 `redesign.css` 迁移**独占**选择器（迁移后层叠位置不影响结果）。已迁 `redesign.css → tools.css` 98 个块，`redesign.css` 4734 → 4195 行。

迁移工具的两个硬约束（都是实测踩出来的，已写进脚本注释）：

1. 选择器必须在**源文件内部也只出现一次** —— `redesign.css` 是多次评审叠加，同一选择器常有新旧两条定义，只搬走一条会改变层叠（实测一次造成 6 处样式变化）。
2. 扫描时必须**屏蔽注释但保留长度**，否则带前导注释的规则会被当成选择器，`owners` 判断失真。

下一步待办（按方案「每次迁移一个区域」）：把 `redesign.css` 里的重复定义先归并（约 21 个 `.rp-*` 选择器有待归并），再继续 rail / chat / composer / browser 各区域的迁移。

### 顺带修掉的一致性问题

`store.ts` 里 20 处 pi 命令调用只判断 `res.ok` 而没有 `try/catch`，pi 未连接时会产生**未捕获的 promise rejection**，用户看不到提示、且不进日志（违背「所有报错都进日志」的既定设计）。已统一收进 `piCall()`，并剥掉 Electron 的 `Error invoking remote method '…'` 前缀。由 `logs` 场景验证。

以下失败经 stash 对比确认**在本次改动前就存在**，属于设计演进后未更新的断言（非回归），已按当前设计改写：

### 重要：等价验证的**边界**（一次失败的尝试）

为了继续压缩 `stage1.css` / `redesign.css`，我写了一个「跨文件选择器合并」工具
（把同一选择器在多个文件里的定义归并到最后一处）。它在 `stage1.css` 上通过了层叠校验，
在 `redesign.css` 上却反复报出 1～8 处真实差异。最后定位到根因：

> `motion.css` 里的 `animation` 定义写在**多选择器规则** `.modal, .settings { … }` 里。
> 而我的工具与 `css-layer-check.mjs` 都是**按选择器字符串分组**的 —— `.modal, .settings`
> 与 `.settings` 被当成两个不同的东西，于是这条覆盖看不见。

结论（已写进工具与本文档）：

| 操作类型 | 当前校验是否能证明等价 |
| --- | --- |
| **不改变声明位置**（迁移、归并重复、删全被覆盖的规则） | ✅ 能。顺序不变 → 覆盖关系不变，模型的盲点不影响结论 |
| **改变声明位置**（把声明搬到别的规则里） | ❌ 不能。模型看不到多选择器与跨媒体查询的覆盖，实测产生了真实差异 |

所以那个工具已删除，未纳入代码库。要安全地做「跨文件合并」，前提是先把校验器升级成
**逐选择器 + 带 `!important` 优先级 + 跨 `@media` 保守处理**的完整层叠模型。

这次踩到的两个具体 bug 已修在保留的工具里（它们同样影响 `css-dead-rules.mjs`）：

1. 解析声明时没抹注释 → 属性名被并进「一段注释 + padding」，覆盖判定静默失效；
2. 跨 `@media` 的覆盖无法静态判定 → 一律跳过（宁可少合并）。
